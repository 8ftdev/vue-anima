# Performance benchmark

Run from the repository root:

```sh
bun run benchmark
```

The command starts a local Vite server and headless Chromium, then prints sample count, median, p95, and mean in milliseconds. Install Chromium with `bunx playwright install chromium` if it is not already present. This benchmark is informational; it is not a CI threshold.

The Vite measurement uses the `StaticTailwind.vue` fixture, which has four static Tailwind candidates. “Fresh instance” means a new `animaTailwind()` instance in an already-running Bun process. It includes reading the Tailwind entry CSS, compiling its design system, parsing the SFC, validating candidates, and generating the manifest. It excludes process/module startup, Vite graph traversal, Vue code generation, and the app's full CSS build. Warm analysis and manifest generation are timed separately on the same plugin instance.

The runtime measurement uses real generated Tailwind CSS in Chromium. Each element is mounted and initialized with an inactive goal before timing. The timed call activates that goal and includes `classGoals` resolution, computed-style reads, controller work, and a real WAAPI animation start. Setup and cleanup are excluded. Each sample times 20 starts and reports milliseconds **per animation**. Each of three rounds warms up for 10 batches and measures 40 batches per scenario; scenario order rotates each round to limit order bias. The reported p95 uses the nearest-rank method. The “manifest class” path uses the manifest generated by the Vite plugin. “Style object” measures the core controller with `{ opacity: 1 }` as a baseline.

Example results from three sequential runs on an Apple M4, macOS Darwin 25.5.0, Bun 1.4.2, Chromium 153.0.8010.12, Tailwind 4.3.3, and Vite 8.3.0. Each cell is the median of that statistic across the three runs:

| Scenario                                | Samples per run |   Median |      p95 |
| --------------------------------------- | --------------: | -------: | -------: |
| Vite fresh instance: analyze + manifest |              40 | 1.586 ms | 7.467 ms |
| Vite warm SFC analysis                  |             120 | 0.014 ms | 0.021 ms |
| Vite warm manifest generation           |             120 | 0.009 ms | 0.013 ms |
| Dynamic class animation start           |     120 batches | 0.285 ms | 0.325 ms |
| Manifest-backed class animation start   |     120 batches | 0.260 ms | 0.305 ms |
| Direct style-object animation start     |     120 batches | 0.045 ms | 0.070 ms |

The manifest-backed path measured about 0.025 ms less per class animation in this fixture. Both class paths still measure the source and target computed styles; the manifest removes target-class CSS rule discovery, so it is not expected to eliminate all runtime work. These are local throughput measurements, not guaranteed per-frame latency or results for other CSS sizes, devices, or browsers.
