# vue-anima: initial design

Status: implemented and verified. Project `vue-anima`, directive `v-anima`.

## Purpose

A small, typed Vue directive that animates an element toward reactive goal styles using native Web Animations API interpolation. Support Vue's regular renderer and Vapor through explicit, tested adapters. Use Bun for all package management, scripts, and command execution.

## Architecture and alternatives

Recommended: a DOM animation controller, thin Vue adapters, and independently imported goal resolver plugins. No VueUse dependency and no JavaScript animation loop. The browser handles interpolation and cubic-bezier timing.

A VueUse wrapper would save some lifecycle work but includes abstractions beyond this library's state-to-goal contract. A template compiler extension could preserve arbitrary custom syntax but adds build integration and compiler coupling. Neither belongs in the first version.

## Proposed public API

Prefer the user's reactive boolean argument for activation, with goal styles in the binding value:

```vue
<div style="opacity: 0" v-anima:[isActive]="{ opacity: 1 }" />

<div
  style="opacity: 0"
  v-anima:[isActive]="{
    styles: 'opacity: 1',
    easing: 'cubic-bezier(0.25, 0.1, 0.25, 1)',
  }"
/>
```

Objects provide property typing; CSS declaration strings are parsed with the browser's CSS parser. An argument of false selects the base state; true selects the goal. Zero is a valid style value. Directive values must be JavaScript expressions, so bare `opacity:1` is not valid binding syntax.

Although Vue's general syntax guide describes string/null dynamic arguments, its custom-directive runtime passes arguments through unchanged and exposes a generic Arg type. Vapor's minor-branch implementation likewise accepts a generic argument getter. Compiled fixtures and template type checking verify the boolean API against the pinned versions.

An extended value may include styles and timing in one object:

```vue
<div
  v-anima:[isActive]="{
    styles: { opacity: 1 },
    duration: 250,
    easing: 'ease-out',
  }"
/>
<div v-anima="{ active: isActive, styles: { opacity: 1 }, duration: 250 }" />
```

When an argument is present it controls activation; otherwise use the object's active field, defaulting to true when omitted. Recommend keeping per-element configuration in this same object to avoid needing a second directive. The approved API keeps configuration in the options object; a separate configuration directive is not included.

Export default directives and a factory for defaults and resolver registration. Config supports duration, delay, and easing, with proposed defaults of 250ms, 0ms, and `cubic-bezier(0.25, 0.1, 0.25, 1)`. Config changes apply to subsequent transitions.

## State and animation contract

1. Capture original inline declarations and read computed base values only for goal properties. Base values may come from stylesheets, inheritance, or browser defaults; explicit inline values are not required.
2. Initial false leaves the element untouched. Initial true applies its goal immediately; mount animation is outside the first version.
3. Activation animates from current rendered values to the goal. Deactivation animates back to the baseline and restores original inline declarations so normal CSS takes over again.
4. An interrupted transition samples its current presentation before canceling. The replacement starts there, avoiding jumps. Stale completion handlers cannot overwrite newer state.
5. Active goal changes animate to the new target; removed properties return to their baseline. Equivalent updates do not restart an animation.
6. Settle final styles and release finished Animation objects. Restore owned declarations and cancel work on disposal. Do not replace unrelated inline declarations.
7. Respect reduced motion and apply targets immediately when WAAPI is unavailable. Server imports must not access browser globals. Hydration captures baseline after mounting.

External code should not write the same inline properties while the directive owns them. Responsive baseline changes during an active animation are outside the first version; after deactivation the original cascade is restored. Discrete/non-interpolable values follow browser behavior; automatic `height:auto` measurement is excluded.

## Plugins and Tailwind

Plugins resolve input into explicit CSS goal properties and provide cleanup where needed. They do not provide a second animation engine. Package subpath exports keep optional plugins out of the default bundle.

With the optional class resolver configured:

```vue
<div
  class="bg-red-200"
  v-anima:[isActive]="{
    styles: 'bg-blue-300',
    easing: 'cubic-bezier(0.25, 0.1, 0.25, 1)',
  }"
/>
```

Class strings are resolved against CSS already generated by the consumer. The plugin does not ship Tailwind or its palette. Goal classes must appear as complete strings in Tailwind's source detection or safelist. Treat the goal as the complete active class list: compare a temporary probe carrying the source element's classes and inline styles with a temporary probe carrying the target classes, then return every changed direct-element computed property. Keep the real class attribute untouched and preserve source computed text color for currentColor.

Check the loaded CSS rules for every target token before measuring so missing compiled classes fail clearly instead of resolving to browser defaults. Multiple utilities, arbitrary values, layout, transforms, colors, and custom classes are supported. Context-dependent selectors use the conditions present during measurement. Pseudo-elements, descendant-only effects, CSS animations, continuously changing interaction variants, and inaccessible cross-origin stylesheets remain outside the contract.

## Engineering constraints

- ESM with declarations and explicit exports; Vue is an external peer dependency.
- Strict TypeScript, unchecked-index checking, exact optional properties, and typed linting that rejects explicit/unsafe `any` and floating promises.
- Small focused modules for controller, CSS input normalization, adapters, configuration, and optional resolver.
- Proposed core budget: at most 2 kB minified + gzip, excluding Vue and optional plugins. Measure built outputs and enforce the budget in CI; this is a target, not a measured claim.
- Bun lockfile, formatting check, lint, typecheck, tests, build, and size check in CI.

## Verification and delivery

Unit tests cover goal normalization, unchanged updates, state transitions, interrupted animations, stale completions, object activation and argument precedence, restoration, and disposal. Real browser tests verify actual interpolation, reduced motion, and Tailwind color resolution. Compile and mount real Vue and Vapor fixtures against pinned versions before advertising compatibility. The implementation targets Vue 3.5.43 and Vue/Vapor 3.6.0-rc.9, with real compiled browser fixtures.

Vapor uses a function receiving value and argument getters and returning cleanup; the regular renderer uses lifecycle hooks and binding objects. Keep these adapters separate, sharing the DOM controller. Vapor's source recommends watchPostEffect for DOM work rather than component lifecycle hooks inside directives.

Deliver source, generated package declarations, README examples, compatibility and plugin limitations, runnable demo fixtures, and measured bundle sizes. No publishing is included.
